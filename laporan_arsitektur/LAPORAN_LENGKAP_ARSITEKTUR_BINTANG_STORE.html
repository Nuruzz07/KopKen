1. Stack & Architecture Overview

A. Pola Struktur Folder & Routing

Kategori Arsitektur: Static Multi-Page Application (MPA)* berbasis Vanilla JavaScript murni (ES6+), HTML5 Semantik, dan Tailwind CSS (CDN dengan Custom Extended Configuration). Sistem tidak menggunakan bundler runtime (zero-build deployment) demi portabilitas tinggi, performa pemuatan instan, dan kemudahan pengujian langsung di lingkungan lokal.
  • Dual-Hierarchy Structure (Root vs Subdirectory Mirrors):
* Root Entrypoints (Akses Cepat): home.html — Landing page portal utama (Hub ekosistem*) yang menyatukan seluruh vertikal bisnis. * kopken.html — Toko online Kopi Kenangan lengkap dengan katalog, modal kustomisasi minuman, bottom sheet keranjang, dan formulir checkout QRIS. * digital-legacy.html — Showcase produk digital & akun premium (Google One AI, ChatGPT, YouTube, Spotify, Canva Pro Lead Magnet). tracking.html — Radar pelacakan pesanan terpadu (Unified Live Tracker) dilengkapi kartu QRIS, timer konfirmasi, dan modul interaktif Bintang SplitPay*. * Subdirectory Mirrors (Modular & Direct Sub-brand): * kopken/ (kopken/index.html, kopken/tracking.html, aset menu lokal). * digital/ (digital/index.html) — Portal produk digital mandiri. * studio/ (studio/index.html) — Portofolio & order bot development/engineering.
  • Prinsip Routing & Navigasi Bersih (No Hashes & Direct File Links):
* Larangan Anchor Hash: Seluruh tautan navigasi internal tidak boleh menggunakan pagar (seperti href="#bento", href="#kopken"). Direct File Extension: Semua tautan internal wajib menggunakan ekstensi .html eksplisit (./home.html, ./kopken.html, ./digital-legacy.html, ./tracking.html) agar tidak terjadi error File Not Found* saat dijalankan di browser lokal (file:///C:/...). * Integritas Relatif Subfolder: Berkas di dalam subfolder (misalnya kopken/index.html) menggunakan path relatif berjenjang naik (../home.html, ../tracking.html, ../assets/).

B. Transisi Halaman Sinematik (The Obsidian Gate)

  • Aset Terpadu: assets/transition.js dan assets/transition.css.
  • Mekanisme Kerja:
Dual-Shutter Shutter: Tirai ganda simetris berbahan Dark Obsidian* (#0c0a09) yang menutup dari atas (gate-shutter-top) dan bawah (gate-shutter-bottom) secara bersamaan dengan aksen garis emas/amber (#d97706). Emblem Asli Concept 6C: Di tengah tirai terdapat emblem SVG asli Bintang Store dengan animasi pendar aura radial bernapas (pulsing breathing aura glow*). * Navigation Interceptor: Mengintersepsi klik pada elemen internal (mengabaikan #, mailto, tel, dan link eksternal), mengunci tampilan, menutup tirai dalam 480–500ms, menyimpan state di sessionStorage (bs_transition_incoming), lalu me-redirect URL tujuan. * Entrance Reveal: Saat halaman tujuan selesai dimuat, skrip membaca sessionStorage dan secara otomatis membuka tirai ke atas dan bawah dalam 450ms. * Transaction Lock: Tombol checkout QRIS memanggil window.triggerTransition('route-tracking', 'MEMPROSES TRANSAKSI AMAN...', callback) untuk efek segel keamanan transaksi sebelum dialihkan ke halaman pelacakan.

2. State Management & Data Flow Saat Ini

A. Pemuatan Data Katalog Produk & Gerai

1. Katalog Kopi Kenangan (menu.json): * Di-load secara asinkron via fetch('./menu.json') di fungsi loadDataFiles() pada app.js. * Struktur hirarki JSON: "Kopi Kenangan" ➔ "satuan" ➔ baru, coffee, nonCoffee, oatside, frappe, food. * Properti per item: id, name, price (harga jastip promo), real_price (harga resmi outlet untuk harga coret), badge, img (URL Supabase Storage bucket menu-kopken), serta flag isFood. 2. Database Gerai / Outlet (outlet.json): * Memuat data 1.328 gerai Kopi Kenangan di seluruh Indonesia. Berisi koordinat presisi (latitude, longitude), jam buka-tutup kasir (hours), status operasional, dan klasifikasi gerai (Mall, Standalone, Signature*). Algoritma Haversine Formula* (calculateDistance) di app.js menghitung jarak gerai terdekat terhadap koordinat GPS pelanggan secara instan. * Logika pengecekan jam operasional WIB otomatis memunculkan banner peringatan jika gerai terpilih akan tutup dalam waktu 30 menit ke depan. 3. Katalog Produk Digital (digital-legacy.html): * Dirender semi-statis dalam format Bento Grid Card. * Pilihan paket harga dioper secara dinamis ke modal checkout via parameter JavaScript: openDigitalCheckoutModal(productName, plans, snkList).

---

B. Alur Keranjang, Form Outlet, & Kalkulasi Harga

1. Kustomisasi Minuman: Modal Racikan Pas di app.js mengelola pilihan suhu (Ice / Hot), ukuran cup (Regular / Large), kadar gula (Normal / Less / No Sugar), kadar es, serta topping. Nilai dikompilasi ke dalam string details. 2. State Keranjang (cart): Array cart disimpan ke localStorage (bintang_cart dan cart) untuk persistensi sesi belanja. 3. Mode Pengambilan: Mendukung Takeaway (ambil di gerai) dan Delivery (Shopee Instan). Pada mode Delivery, form memvalidasi alamat lengkap serta tautan Google Maps, dan mengenakan tarif pengiriman Rp 5.000. 4. Evaluasi Cart Booster 50k: Logika progress bar menghitung selisih subtotal menuju target Rp 50.000. Saat syarat terpenuhi, sistem mengaktifkan status Kualifikasi VIP Terpenuhi untuk membuka akses gratis Bot Radar GetContact VIP. 5. Kode Promo (Maintenance Mode): Input voucher tetap tampil secara visual, namun saat tombol Terapkan diklik, sistem memunculkan toast informasi: "Fitur kode promo sedang dalam pemeliharaan berkala." tanpa memotong tagihan (discount = 0). 6. Validasi Formulir: Tombol checkout memeriksa kelengkapan nama pemesan (minimal 2 karakter), nomor WhatsApp aktif (minimal 9 digit), data alamat (jika delivery), dan info rekening Host (jika split bill aktif).

C. Alur Checkout ke Supabase & Bot Telegram

Saat tombol "Lanjut ke Pembayaran QRIS" ditekan di kopken.html, fungsi executeFullOrderFlow() menjalankan serangkaian proses paralel: 1. Unggah QRIS Host: Jika Split Bill aktif dan Host melampirkan gambar QRIS, berkas diunggah ke Supabase Storage bucket receipts dengan nama berkas host_qris_${orderId}.${fileExt}. 2. Upsert ke Database Supabase (orders): Menyimpan data pesanan baru tanpa mengubah skema relasional tabel: `javascript await supabaseClient.from('orders').upsert([{ id: orderId, customer_name: name, customer_wa: cleanWa, outlet_name: activeOutlet, order_type: currentOrderType, // 'takeaway' | 'delivery' delivery_fee: deliveryFee, delivery_address: currentOrderType === 'delivery' ? deliveryAddress : null, delivery_maps_url: currentOrderType === 'delivery' ? deliveryMapsUrl : null, order_items: structuredOrderItems, // Array JSONB memuat metadata split_info total_price: grandTotal, estimated_profit: Math.round(grandTotal * 0.25), status: 'menunggu_pembayaran' }]); ` 3. Dispatch Notifikasi Bot Telegram: Mengirim pesan HTML lengkap ke Admin Telegram Chat ID (6731058601) berisi Order ID, cabang outlet, rincian menu, info pengantaran, data patungan split bill, link pelacakan langsung, dan tautan direct WhatsApp pelanggan. 4. Pembersihan & Redirect: Mengosongkan keranjang, menyimpan data ke riwayat lokal (bintang_history), memicu transisi segel The Obsidian Gate, dan mengarahkan ke ./tracking.html?order_id=${orderId}.

---

D. Alur Pelacakan Realtime & Bintang SplitPay (tracking.html)

1. Realtime Listener: Berlangganan kanal Supabase Realtime Postgres Changes: `javascript supabaseClient.channel(order_tracking_room_${orderId}) .on('postgres_changes', { event: '*', schema: 'public', table: 'orders', filter: id=eq.${orderId} }, (payload) => { renderOrder(payload.new); }).subscribe(); ` 2. Siklus 5 Status Pesanan: * menunggu_pembayaran ➔ Menampilkan QRIS dinamis & rincian nominal tagihan. * menunggu_konfirmasi ➔ Bukti transfer terkirim, timer hitung mundur konfirmasi admin (15–30 menit) aktif. * sedang_diproses ➔ Pembayaran terverifikasi, barista meracik kopi / akun digital disiapkan. * selesai ➔ Tiket antrean pengambilan / pesanan meluncur via kurir instan / kartu garansi digital aktif. * dibatalkan_pelanggan ➔ Formulir pengajuan refund dana ke rekening pembeli aktif. 3. Modul Interaktif Bintang SplitPay (Split Bill Radar): * Membaca metadata split_info pada array order_items. Menghitung pembagian proporsional ongkir dan diskon per teman (pro-rata share*). Menyediakan tab pill per anggota tongkrongan, sapaan personal hangat ("Hai {nama}, total bagian kopimu: Rp {nominal}"), box nomor rekening Host dengan 1-tap copy*, pratinjau QRIS Host dengan border emas bercahaya, serta tombol salin format pesan WhatsApp grup.

3. Coding Style & Development Pattern

A. Pola Penulisan JavaScript

  • Vanilla Modular State: Variabel state dideklarasikan secara terorganisir di scope atas (cart, selectedOutlet, isExecutingOrder, currentAppTab).
Audio Synthesizer Engine: Class SoundEffectsEngine memanfaatkan Web Audio API bawaan browser untuk menghasilkan efek ketukan (sine wave 1200->800 Hz) dan chime sukses (triangle wave chord C5->E5*) secara sintetis tanpa ketergantungan file audio eksternal .mp3.
  • Standard Helper Utils:
* Format Rupiah: const formatRp = (num) => 'Rp ' + parseInt(num || 0).toLocaleString('id-ID'); * Waktu Indonesia Barat: getWIBDate() menyelaraskan waktu ke UTC+7 (WIB) terlepas dari zona waktu perangkat pengguna.
  • Cyber-Luxury Toast System: Fungsi showToast(pesan) menginjeksikan komponen notifikasi kustom bertema Dark Obsidian (#1C1917), border aksen amber (#F59E0B), dan animasi transisi halus sebagai pengganti mutlak dialog alert() bawaan browser.

5. Hal-hal yang Perlu Konsistensi (Aturan Emas Repositori)

Demi menjaga keutuhan sistem dan mempermudah integrasi masa depan (seperti modul Janji Jiwa, Tomoro Coffee, atau backend multi-brand), 6 aturan tak tertulis berikut wajib dipertahankan 100%:

1. Integritas Skema Supabase (Zero Root Column Breaking)

  • Tabel orders di Supabase memiliki kolom root yang telah terhubung ke bot Telegram admin.
  • Aturan: Segala data tambahan baru (metadata split bill, catatan racikan, status reimbursement, maupun identitas multi-brand) wajib disimpan ke dalam kolom JSONB order_items. Dilarang menambah kolom baru di tabel root Supabase secara sepihak agar parser webhook Telegram admin tidak mengalami crash.

2. Sinkronisasi File Ganda (Root vs Subfolder Mirrors)

  • Setiap kali melakukan pembaruan pada modul Kopi Kenangan maupun Tracking, perubahan wajib diterapkan serentak pada kedua pasangan berkas:
* kopken.html (root) ⬄ kopken/index.html (subfolder) * tracking.html (root) ⬄ kopken/tracking.html (subfolder)
  • Perhatikan perbedaan kedalaman path (./assets/ di root vs ../assets/ di subfolder).

3. Nomenklatur Order ID per Brand

  • Format ID pesanan digunakan oleh tracking.html untuk menentukan template tiket dan alur pelacakan:
* Kopi Kenangan: kk-{nama}-{timestamp4} * Produk Digital: dig-{nama}-{timestamp4} * Brand Baru (Janji Jiwa): jj-{nama}-{timestamp4}

4. Hirarki Multi-Brand pada menu.json

  • Di menu.json, key terluar saat ini adalah "Kopi Kenangan".
  • Saat menambahkan brand baru, posisikan sebagai sibling key baru di level terluar:
`json { "Kopi Kenangan": { "satuan": { ... } }, "Janji Jiwa": { "satuan": { ... } } } ` Hindari mengubah struktur key "satuan" yang sudah ada agar fungsi render katalog eksisting tetap stabil.

5. Larangan Dialog Bawaan Browser (No alert() / confirm())

  • Dilarang keras menggunakan alert(...) atau confirm(...) bawaan browser.
  • Selalu gunakan showToast(pesan) untuk notifikasi status atau modal popup kustom bergaya Dark Obsidian untuk menjaga standar Cyber-Luxury UX.

6. Navigasi Bersih Tanpa Anchor Hash

  • Dilarang menggunakan tautan internal berbasis hash (href="#...").
  • Seluruh navigasi antar-modul wajib menggunakan direct file link bersih (./home.html, ./kopken.html, ./digital-legacy.html, ./tracking.html`).
